# 01 模块定位与设计原则

## 1.1 模块定位

**生态协同**是数字孪生空间底座的重要组成部分，用于管理**不占用实体空间**的虚拟侧资源，包括：

1. **虚拟入孵项目**（与实体项目可建立关联）  
2. **外部合作机构**（CRO、医院、高校、检测机构等）  
3. **AI 能力节点**（模型、智能体、Skill 等，V1 以静态展示为主）  
4. **知识库**（公共 / 行业 / 私有，与资源运营解耦）

通过**独立二级菜单**将四类资源拆分，使用户按类型管理与使用，职责清晰。

## 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **职责独立** | 每个二级菜单只管理一种资源类型，避免「大杂烩」配置页。 |
| **权限清晰** | 各子模块访问权限单独控制（路由 + 接口 + 按钮级）。 |
| **扩展友好** | 后续增加「虚拟项目申请流程」、地图可视化、AI 中台同步等，不破坏其他子模块契约。 |
| **版本分层** | **V1**：基础 CRUD + 关联展示 + 列表筛选导出 + 二次确认删除；**V2**：地图可视化、AI 中台自动同步、调用测试、文档级权限等。 |

## 1.3 与数字孪生空间的关系

- **孪生侧**：侧重实体空间、占用关系、资源空间分布。  
- **生态协同侧**：侧重**非实体占用**的协作资源与知识/AI 节点。  
两者在「项目」维度上可通过**关联实体项目**字段交叉引用，但数据模型独立，避免孪生台账被非空间数据污染。

## 1.4 非目标（V1 明确不做）

- 文档级细粒度权限（仅库级）。  
- AI 能力真实调用链路与计费。  
- 与地图引擎的深度联动（V2）。  
- 复杂工作流引擎驱动的跨模块审批（可先用状态 + 简单校验代替）。
