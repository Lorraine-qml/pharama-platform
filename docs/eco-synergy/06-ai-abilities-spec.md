# 06 AI 能力 — 功能与界面需求

## 6.1 功能清单（版本划分）

| 功能 | V1 | V2 |
|------|----|----|
| 列表展示 | 静态配置或本地 JSON 渲染 | 对接 AI 中台自动同步 |
| 查看详情 | 弹窗：描述、版本、调用方式、**模拟**使用统计 | 真实指标与日志 |
| 测试调用 | 按钮置灰 + Tooltip「开发中」 | 沙箱调用 / 配额 |
| 同步 AI 中台 | 按钮置灰或 Toast「V2」 | 轮询 / Webhook 同步 |
| 刷新 | 重新拉取静态数据或本地 seed | 刷新缓存与中台状态 |

## 6.2 列表页布局（线框）

- 标题：`AI能力` + `[刷新]` + `[同步AI中台(V2)]`（禁用态）  
- 表格列：`名称` | `类型` | `描述` | `状态` | `操作`  
- **类型枚举**：大模型 / 智能体 / Skill / 知识库节点（若与知识库重复展示，需在文案区分「AI 侧能力节点」vs「文档知识库」）  
- **状态**：`🟢 在线` `🟡 维护中` `⚫ 离线`（颜色与图例统一，见 09 文档）

## 6.3 详情弹窗（V1 占位）

展示字段示例：

- 类型、版本、描述  
- 调用方式：`REST API` / `SDK` / `MCP` 等  
- 使用记录（近 30 天）：**模拟**调用次数、成功率  
- 操作：`[调用测试(V2)]` 禁用；`[查看文档]` 外链或抽屉 Markdown  

## 6.4 数据模型（建议）

```text
AiAbilityNode {
  id, name, kind, version, description, invokeKind, status,
  stats30d: { calls, successRate }  // V1 mock
}
```

## 6.5 验收要点

- 列表与详情仅只读；无删除入口（避免误删中台注册资源，V2 由中台管理）。  
- 所有「同步」「测试」类按钮在 V1 有明确禁用原因提示。
